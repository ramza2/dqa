# S-04-B Snapshot revision history: append-only repository foundation

**Status:** Draft implementation, not deployed or database-migrated.
Depends on S-04-A (`compare_schema_snapshots`) merged in PR #72.

## Current scope

- New PostgreSQL **DQA-owned** `schema_snapshot_revisions` table for
  immutable metadata-only physical snapshots. This is **not** a replacement
  for the existing `catalog_import_revisions`, `catalog_active_revisions`
  or `catalog_activation_events` tables.
- One append operation: `capture_snapshot_revision(session, snapshot,
  source_name, captured_by, capture_request_id, expected_previous_revision_id)`.
  Call only from future reviewed/authorized Inspector service. It does not
  connect to Oracle, has no public POST endpoint and never imports/activates.
  Caller **must commit or roll back** the DQA session itself. Do not claim a
  result is durable before commit succeeds.
- PostgreSQL transaction-scoped advisory lock scoped by `source_name`
  serializes concurrent appends. `expected_previous_revision_id` is a
  compare-and-set guard; if another successful capture wins, the later
  caller gets `STALE_SNAPSHOT_REVISION`, not a silent overwrite.
- `(source_name, capture_request_id)` unique idempotency identity; a
  duplicate consistent retry reuses the same revision, but a changed payload
  or different actor or predecessor returns `CAPTURE_REQUEST_REUSED`.
  UUID is generated by the trusted caller and **not** accepted as a
  credential/authentication mechanism.
- Each revision stores: source/database/schema, version 1, deterministic
  DQA physical fingerprint, predecessor revision id, captured-by actor,
  DQA timestamp, six physical object classes, per-type counts and
  compared summary/field-name changes. Raw default SQL expressions and
  index-definition SQL are excluded from the sanitized physical payload.
- Capture with no predecessor stores `NO_BASELINE`, never zero-diff.
  Corrupt/mismatched/unsupported old Snapshot blocks capture rather than
  silently building a new baseline. No independent readiness/preflight.
- Minimal read-only, existing `CATALOG_READ`-guarded endpoints:
  - `GET /api/v1/schema-inspector/snapshots?source_name=...&limit=...&offset=...`
  - `GET /api/v1/schema-inspector/snapshots/{revision_id}?source_name=...`
  - Responses exclude raw `snapshot_json` and `capture_request_id`.
    Detail contains only changed object identities and changed field names,
    **not** before/after values.
  - Source-scoped detail access, unknown revision => 404.
- Migration `20261014_ss01` follows `20261008_dd02`. **Deployment
  requires operator-reviewed `alembic upgrade head` before application
  startup**, because DQA enforces Alembic head on startup. This PR must
  not modify the live database until explicitly approved. Destructive
  downgrade of historical rows deliberately blocked.

## Not in this PR

- No Inspector Oracle connectivity changes, runtime capture endpoint, schedule,
  auto-sync, automatic Catalog Package generation/import, READY gate,
  active Catalog pointer update, Data Discovery rebuild or clinical data read.
- No migration of PoC DB or changes to the independently running PoC.
- No real DEMIS authorization or production IdP policy.
- No automatic pruning; retention/legal hold policy needs written agreement.

## Gates before any merge/deployment

   tests/test_schema_inspector_admin.py`.
2. Isolated PostgreSQL migration + capture transaction tests, including
   concurrent source capture, idempotent retry, stale predecessor,
   rollback, listing/404 and actual DB unique constraint.
3. Confirm no `catalog_active_revisions` or existing READY Revision #1
   modified; do not deploy/apply migration to the operational DQA DB
   until the changes and rollback/backup plan are reviewed.
4. S-04-C separately defines capture API approval, Snapshot review, preflight,
   READY eligibility, explicit Catalog import/activation and failure handling.

**Source authority:** A captured Snapshot is informational history only.
The existing explicitly activated READY Catalog remains query authority.
