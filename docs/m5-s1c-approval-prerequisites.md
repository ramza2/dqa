# M5-S1C — 기관 승인 전 연계·LLM 활성화 선결사항 (2026-11-02)

> 이 문서는 미결정 사항을 정리한 **개발용 확인표**이다. 승인서, 기관 협의 결과, 실제 서비스 접근 권한을 대신하지 않는다.

## 적용 상태

- **외부 서비스 클라이언트**: DRAFT/REVOKED 정책 초안 및 감사만 제공. 인증·인가·키 발급/활성화 없음.
- **LLM**: 개발용 로컬 후보·서버 정책 검토 및 고정 URL 메타데이터 시험만 조건부 허용. 운영 모델 활성화와 임상정보 전송 권한 없음.
- **기본 업무 흐름**: LLM-free, 승인된 Query Template, 결정적 SELECT-only 검증 및 기존 조회 감사 그대로 유지.
- 관리 화면은 아래 선결사항을 읽기 전용으로 보여준다. 체크박스·승인 저장·활성화 API가 아니다.

## 2. 개발 순서와 통과 조건

1. **M5-S1C(본 단계)**: 위 선결사항을 관리자 UI에 읽기 전용으로 표시하고, 활성화 조작/외부 요청이 추가되지 않는 회귀 테스트 작성.
2. **CPU Query Assistant**: 승인·활성화 템플릿 탐색 → 파라미터 입력/검증 → Preview → 조회 실행의 오류 안내·접근성 및 상태 일관성 개선. 실제 외부 데이터 대신 Oracle Mock 격리 테스트.
3. **실기관 연계**: 확인된 계약/승인 증빙에 따라 인터페이스 문서·검증 시나리오를 갱신. 승인이 확보되기 전까지 FHIR/SNUH.AI/실 DEMIS 네트워크 호출 및 서비스 인증 구현·활성화 금지.
4. **M5-S2/M5-L1 운영 변경**: 별도 승인, 독립적인 보안 설계/코드 리뷰·회귀 시험 및 배포 절차를 거쳐야만 검토. 본 단계와 별개다.

## 3. 검증과 배포

- 프론트엔드 격리 검증: `bash scripts/dqa-m5-l1d-frontend-runtime-test.sh` (기존 M5 UI 테스트 포함).
- 추가 회귀: 관리자 허용 시 선결사항 노출, 블록 내부 활성화 버튼 없음, 기존 기본 OFF 정책 유지.
- 백엔드 API/DB 스키마/환경변수/운영 설정 변경 없음. **DQA 서버 재배포 불필요**.
- 본 문서의 미결정은 승인 완료나 실제 연계 검증 완료를 뜻하지 않는다.
